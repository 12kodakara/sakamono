# サカモノ

**海外サッカーグッズ、日本までいくら？**

海外クラブ公式ストアのサッカーグッズを、国際送料や輸入コストを含んだ
**日本到着推定額**で国内価格と比較できるサイトです。

> ## ⚠️ いまは「第3段階」です
>
> 現在このサイトが表示している価格・在庫・割引率・為替レートは、
> **すべて動作確認用のサンプル値**です。実際の販売情報ではありません。
> 外部サイトやAPIからの価格取得は行っていません。
>
> サンプル表示中は、画面の一番上に黄色い帯で「開発中のサンプル表示です」と出ます。
> この帯はデータの出どころが本番へ切り替わると自動的に消えます。
>
> 第2段階で**価格比較エンジン**、第3段階で**外部データの取り込みパイプライン**を作りました。
>
> ### 🔴 Liverpool 公式ストアの自動取得は行いません
>
> 調査の結果、公式ストアの利用規約 第15.7条が
> 「自動・体系的な抽出」「別データベースへの取り込み」「再配信」を
> 明示的に禁止していることが分かりました。
>
> 代わりに **Webgains 公式商品フィード（プログラムID 7413）** を正規の入手経路として推奨します。
> 調査結果: [docs/data-sources/liverpool.md](docs/data-sources/liverpool.md)

## 1. このサイトは何をするのか

海外の公式ストアで「£79.95」と書いてあっても、日本に届くまでにいくらかかるのかは分かりません。
送料も、関税も、カード会社の手数料もかかるからです。

サカモノは、その合計を**日本到着推定額**として計算し、国内価格と並べて表示します。

```
海外価格 £79.95
   ↓ 円換算・送料・輸入コスト・決済コストを加算
日本到着推定額 19,148円
   ↓ 国内価格（送料込み）と比較
国内価格 21,800円  →  「国内より 2,652円 安い」
```

### 対象リーグ（5リーグ）

Premier League / La Liga / Serie A / Ligue 1 / Eredivisie

Bundesliga は現段階では対象外です。最終的には約100クラブ規模を想定しています。

### 表示しているクラブ（4クラブ）

Liverpool / Tottenham Hotspur / FC Barcelona / Real Madrid

### 守ってほしいルール

1. **画面（`app/` と `components/`）は計算をしない。**
   金額の足し算・割り算・しきい値の判定は、すべて `src/domain/services/` にあります。
   画面は計算済みの値を受け取って表示するだけです。

2. **画面は `data/fixtures/` を直接 import しない。**
   必ず `data/repository.ts` を通します。
   こうしておけば、データの出どころが外部APIに変わっても画面を書き換えずに済みます。

3. **`repository.ts` も計算式を持たない。**
   「どのデータをどのサービスへ渡すか」を決める配線係に徹します。

4. **色・余白・文字サイズは `globals.css` の先頭にあるデザイントークンを使う。**
   `#0f5f4a` や `13px` を直接書かないでください。

## 6. データ構造

定義は [`src/domain/types.ts`](src/domain/types.ts) にあります。

```
League（リーグ）
  └─ Club（クラブ）
       └─ Product（商品そのもの）
            ├─ StoreListing（あるショップでの掲載情報）──→ Store（販売元）
            │      └─ PriceSnapshot（その掲載の価格履歴）
            └─ DomesticMatch（海外商品と国内掲載の照合結果）

ExchangeRate（為替レート） / ShippingRule（送料の決まり） / ImportCostRule（輸入コストの見積り方）
  … ストアや通貨に紐づく「計算の前提」。第2段階で追加。
```

### いちばん大事な区別: Product と StoreListing

| | Product | StoreListing |
| --- | --- | --- |
| 何を表すか | 商品そのもの | **あるショップでの**掲載情報 |
| 例 | 「リヴァプール 2025/26 ホーム レプリカ」 | 「公式ストアでの £79.95・在庫あり」 |
| 変わるもの | ほぼ変わらない | 価格・在庫が日々変わる |

同じユニフォームでも、公式ストアと国内ショップでは価格もURLも在庫も違います。
これを1つにまとめてしまうと、比較ができなくなります。**必ず分けてください。**

### Money 型（第2段階で追加）

金額を「ただの数字」で持ち回ると、**それがポンドなのか円なのか分からなくなります。**
「ポンドの金額に円の送料を足す」といった間違いは、数字だけではコンパイラに見つけられません。

```ts
interface Money {
  amount: number
  currency: 'JPY' | 'GBP' | 'EUR' | 'USD'
}
```

計算サービスはすべて `Money` を受け取り、**通貨が違う金額を足そうとするとその場でエラー**になります。

**丸めの方針**（[`src/domain/money.ts`](src/domain/money.ts)）

- 円は小数を持たない → **常に整数円へ丸める**
- 外貨は最小単位（2桁）まで保持する
- 丸めは「0から遠い方へ half up」で統一（`Math.round` は `-0.5` を `0` にしてしまい、符号で挙動が変わるため）
- 丸めるのは「通貨をまたぐ計算の直後」と「表示の直前」だけ。途中では丸めない

> `StoreListing` などの保存用の型は `currency` と `currentPrice` を別々のフィールドで持っています。
> JSONとしてやり取りしやすい形を保つためで、**計算に入る時点で必ず `Money` へ包みます。**

## 7. 価格計算エンジン

第2段階の中心です。[`src/domain/services/`](src/domain/services/) にあります。

| ファイル | 役割 |
| --- | --- |
| `exchange.ts` | 円換算。未対応の通貨・レート無しは**失敗として返す**（0円にしない） |
| `shipping.ts` | 送料の解決（fixed / threshold / estimated / unknown） |
| `importCost.ts` | 輸入コストの見積り（前提値はデータ側に持つ） |
| `paymentCost.ts` | 決済・為替関連コスト（海外事務手数料） |
| `landedCost.ts` | **日本到着推定額**（上の4つを合計する） |
| `variantMatch.ts` | レプリカ／オーセンティックなどの取り違え防止 |
| `domesticPrice.ts` | 国内比較価格の選択 |
| `priceComparison.ts` | 海外と国内の比較結果 |
| `discount.ts` | 割引率（値上げをセール扱いしない） |
| `priceHistory.ts` | 価格履歴のまとめ（現在／過去最安／過去最高／直近変動） |
| `freshness.ts` | 価格データの鮮度 |
| `saleSignals.ts` | 注目セール判定の材料 |

### 計算式

```
日本到着推定額
  = 商品価格の円換算
  + 国際送料
  + 輸入コスト推定
  + 決済・為替関連コスト

価格差 = 国内比較価格 － 日本到着推定額
         プラス … 海外が安い ／ マイナス … 国内が安い

savingRate = 価格差 ÷ 国内比較価格 × 100   （国内比較価格が0なら null）
```

### 送料の4タイプ

| タイプ | 意味 | 結果 |
| --- | --- | --- |
| `fixed` | 日本まで固定送料 | 金額（確定） |
| `threshold` | 一定金額以上で送料無料 | 条件を満たせば0円、満たさなければ金額 |
| `estimated` | 決済画面でしか確定しない | 金額（**推定**と表示） |
| `unknown` | 分からない | **null**（★0円にしない★） |

### 関税・消費税の扱い

サカモノは税関ではないため、**確定税額は出せません。**
そこで「どういう前提で見積もるか」を [`importCostRules.ts`](src/data/fixtures/importCostRules.ts) に
**データとして持ち**、計算処理はその前提どおりに足し算をするだけにしています。

結果には必ず状態が付きます。

- `estimated` … 前提にもとづく推定額
- `not_applicable` … かからない（国内購入など。**本当に0円**）
- `unknown` … 見積もれない（**0円ではない**）

### 現在の前提（すべて仮の値）

| 項目 | 値 | 置き場所 |
| --- | --- | --- |
| 為替 | 1GBP = 198円 / 1EUR = 168円 / 1USD = 155円 | `lib/pricing/config.ts` → `fixtures/exchangeRates.ts` |
| 国際送料 | ストアごとに設定 | `fixtures/shippingRules.ts` |
| 課税価格 | 海外小売価格の60% | `fixtures/importCostRules.ts` |
| 少額免税 | 課税価格 10,000円以下なら非課税 | 同上 |
| 関税率 | カテゴリごとに 3〜10% | 同上 |
| 消費税 | 10% | 同上 |
| 通関手数料 | 課税される場合のみ 1,100円 | 同上 |
| 海外事務手数料 | 商品代金の2.2%（円建てストアはゼロ） | `lib/pricing/config.ts` |

為替レートには `kind: 'development-fixture'` が入っており、
**実勢レートではないこと**が型として分かるようになっています。
画面にも「開発用の想定値です。実勢レートではありません」と表示されます。

## 8. 「不明」を0円にしない

第2段階でいちばん重要な決まりです。

```
商品代 7,000円
送料   不明
輸入   1,000円
```

このとき **「日本到着推定額 8,000円」と表示してはいけません。**
分からない費用を0円として足すと、実際より安く見えてしまうからです。

サカモノは次のように扱います。

```
totalJpy        = null          ← 合計は出さない
partialTotalJpy = 8,000         ← 分かっている分だけの参考額
missing         = ['shipping']  ← 何が分からないのか
status          = 'incomplete'
```

画面では「**国際送料を除く参考額 8,000円**」と表示し、
その下に「国際送料が分からないため、日本到着推定額は算出できません。」と書きます。

また、価格差も出さず、価格差ランキングにも載せません。

### 0円 と 不明 は別物

| 状態 | 意味 | 金額 |
| --- | --- | --- |
| `not_applicable` | 本当にかからない（国内購入の関税など） | `0` |
| `free` | 条件を満たして送料無料になった | `0` |
| `unknown` | いくらか分からない | `null` |

## 9. 国内価格の選び方

**国内で見つかった最安値をそのまま採用してはいけません。**
フリマ・モールには中古・非正規・別バリエーション・マーキング違いが混ざるためです。

次の順に絞ってから、残ったものの中で最安を選びます
（[`src/domain/services/domesticPrice.ts`](src/domain/services/domesticPrice.ts)）。

| 審査 | 落ちたときの理由コード |
| --- | --- |
| 1. 商品同定が十分か（ランクA/B、または人が確認済み） | `low-confidence` |
| 2. バリエーションが一致しているか | `variant-mismatch` |
| 3. 販売元が信頼できるか（モール型は人の確認が必要） | `untrusted-store` |
| 4. 在庫があるか | `out-of-stock` |
| 5. 国内送料の条件が分かるか | `shipping-unknown` |

**2は confidence より強い判断材料です。**
商品コードが一致していても、レプリカとオーセンティックが食い違っていれば比較しません。

除外した掲載は捨てずに残し、商品詳細ページに
「比較対象から外した国内の掲載」として理由つきで表示します。
黙って安い出品を無視すると、かえって不信感につながるためです。

> 国内価格は**国内送料を含めた総額**で比べます。
> 送料込みの日本到着推定額と条件をそろえるためです。

## 10. 商品一致の信頼度

定義は [`src/lib/matching/confidence.ts`](src/lib/matching/confidence.ts) の**1か所だけ**にあります。

| ランク | ConfidenceLevel | confidence | 意味 |
| --- | --- | --- | --- |
| **A** | `highest` | >= 0.95 | メーカー公式・国内正規専門店、または完全な商品同定 |
| **B** | `high` | >= 0.85 | JAN / EAN / メーカーSKU による高確度の一致 |
| **C** | `medium` | >= 0.70 | 商品属性による一致 |
| **D** | `review` | < 0.70 | 曖昧一致 |

**公開している価格比較へ自動で使ってよいのは A / B のみ。** C / D は管理者の確認対象です。

| 照合手段 | confidence | ランク |
| --- | --- | --- |
| EAN / JAN 完全一致 | 0.99 | A |
| 人が目視で確認（manual） | 0.99 | A |
| メーカー品番一致＋クラブ一致 | 0.90 | B |
| 属性一致 | 0.70 | C |

> 第1段階では C のしきい値を 0.65 にしていましたが、
> 第2段階のランク定義（C >= 0.70）に合わせて 0.70 へそろえました。
> 0.65〜0.70 の値を持つデータは存在しないため、既存の判定結果は変わっていません。
> 自動掲載の下限（0.85）は第1段階から変えていません。

**ランクは「商品同定の確からしさ」だけを表します。**
「誰が売っているか」は別の判定（`isTrustedDomesticStore`）で見ます。
ランクAの定義に「正規専門店」が含まれるのはこの2つを合わせた結果です。

> 判定エンジン（商品同士を突き合わせて confidence を算出する処理）は
> **第2段階でもまだ実装していません。** 第3段階で `src/lib/matching/engine.ts` を追加します。

### 「分からない」の扱い方（第3段階でいちばん大事なところ）

推測で埋めるくらいなら、分からないままにします。

| 項目 | 分からないとき | なぜか |
| --- | --- | --- |
| Replica / Authentic | `'unknown'` | 価格が1万円以上違う。取り違えると比較が壊れる |
| シーズン | `null` | 年式違いは別商品 |
| ユニフォームの種類 | `'unknown'` | ホーム/アウェイは別商品 |
| 対象（メンズ等） | `'unknown'` | メンズとウィメンズは別商品 |
| カテゴリ | `'other'` | 無理に分類しない |
| メーカー | `'確認中'` | 取得元に項目が無い。Nike と決めつけない |
| サイズごとの在庫 | `'unknown'` | 「在庫あり」と書いてあっても全サイズとは限らない |
| 日本向け送料 | `ShippingRule.type = 'unknown'` | 根拠のない固定送料を置かない |
| 商品画像 | プレースホルダー | 外部画像の利用条件が未確認。URLは記録だけする |

`'unknown'` の商品は、第2段階で作った仕組みにより
**自動的に価格比較の対象から外れます**（安全側に倒れます）。

送料が `unknown` なので、Liverpool データを表示すると
日本到着推定額は出ず、**「国際送料を除く参考額」**と表示されます。これは正しい挙動です。

- **キーをソース・README・fixture・テスト・スクリーンショットへ書かないでください**

```bash
npm run data:yahoo:search -- --product=<id> --sample --dry-run

# 実APIを使う（Client ID が必要）
npm run data:yahoo:search -- --product=<id>
```

**一度に多くの商品を検索しないでください。** まず1商品、慣れても5商品までです。

### 検索の順番（強い手掛かりから）

| Level | 手掛かり | 自動採用 |
| --- | --- | --- |
| 1 | JANコード完全一致 | ○ |
| 2 | EAN（**日本の国コード 45/49 で始まる場合のみ**）をJANとして検索 | ○ |
| 3 | メーカー品番 + クラブ名 | ○ |
| 4 | 商品属性（クラブ・シーズン・種別・メーカー） | **×（候補発見用のみ）** |

**EANだからといって自動的にJAN扱いしません。**
JANは EAN のうち日本で採番されたものです。英国で採番されたEAN（50〜）を
国内JANとして検索して見つかった場合、それはむしろ別商品の可能性が高くなります。

Level 4 は信頼度の上限を **0.84（ランクC）** にしてあり、
属性がすべて一致しても自動採用には届きません。

### 商品照合エンジン

[`src/lib/matching/engine.ts`](src/lib/matching/engine.ts)

**点数を足し引きするだけでは足りません。**
レプリカとオーセンティックは「少し似ていない」のではなく「別の商品」です。
点数を下げるだけだと、他が全部一致していれば合計で基準を超えてしまいます。

そこで **hardReject**（これが食い違ったら、他が何点でも不採用）を別に用意しています。

| 食い違ったら不採用 | 理由 |
| --- | --- |
| クラブ | リヴァプールにマンU商品を当てない |
| シーズン | 24/25 と 25/26 は別商品 |
| **レプリカ／オーセンティック** | 1万円以上値段が違う |
| ホーム／アウェイ／サード | 別商品 |
| **メンズ／ウィメンズ／キッズ** | 子供用が大人用の最安値になってしまう |
| メーカー | adidas に Nike を当てない |
| 新品／中古 | 新品価格の比較が目的 |
| JANが両方あって不一致 | 別商品 |

| 要確認へ送る（捨てないが自動採用もしない） | 理由 |
| --- | --- |
| **JANは一致するが属性が食い違う** | モールでは出品者が別商品へ同じJANを付けることがある。こちらの解釈違いの可能性もあるので人が見る |
| マーキング（背番号・選手名）入り | 無地と同じ価格では比べられない |
| 新品かどうか分からない | 新品と決めつけない |
| **相場より極端に安い** | 正規品でない可能性。**安いことを理由に信頼度を上げない** |

### 自動採用の条件

次を**すべて**満たしたものだけが国内価格の比較に使われます。

```
ランクA または B
  かつ hardReject でない
  かつ 要確認でない
  かつ 新品
  かつ 在庫あり
  かつ 送料の条件が分かる（総額を出せる）
```

モール型（出品者が個別にいるサイト）の掲載は、第2段階の仕組みにより
「人の確認済み」か「照合エンジンの自動検証を通過」のどちらかが必要です
（`DomesticMatch.verification`）。

### 国内価格のまとめ方

- **最安値・中央値は「送料込みの総額」**（海外側の日本到着推定額と条件をそろえるため）
- **店舗数は、APIが返した件数ではなく、採用できた候補の件数**
- **候補が0件なら `null`。0円にしません**
- 「条件付き送料無料」は総額を出せないので比較に使いません

### 通信のきまり

| 項目 | 設定 |
| --- | --- |
| リクエスト間隔 | 1.5秒以上（公式制限は1クエリ/秒） |
| 同時実行 | しない（必ず1件ずつ） |
| タイムアウト | 10秒 |
| 再試行 | timeout / 429 / 5xx / 通信断 のみ、最大2回 |
| **再試行しない** | **429以外の4xx**（何度送っても結果は同じ） |
| キャッシュ | `.cache/yahoo/`（TTL 6時間・gitignore済み） |

### 画面で確認する

## 15.5. 誤一致を防ぐしくみ（第4.6段階）

実データで確かめたところ、属性の点数を足し算するだけでは
**別商品を同じ商品として採用してしまう**ことが分かりました。
第4.6段階では、その穴をふさぐしくみを入れています。

### なぜ点数だけでは足りないのか

同じリヴァプール 2025/26 ホームでも、実際の出品はこう分かれています。

| 商品 | 品番 | 国内最安 |
| --- | --- | --- |
| 半袖・無地 | JV6423 | 7,920円 |
| 長袖・無地 | JV6456 | 10,010円 |
| ジュニア・無地 | JV6436 | 5,610円 |
| 半袖・サラー11番入り | JV6423 | 14,410円 |
| アウェイ・無地 | JV6487 | 9,240円 |

**いちばん危ないのは、いちばん下から2行目です。**
サラー入りは無地と**品番が同じ**です。マーキングは後から入れるためです。
クラブもシーズンも種類も袖丈もメーカーも一致します。
点数を足すと満点になりますが、価格は6,490円違う別商品です。

### 判定の順番

```
1. 項目ごとに 一致 / 不一致 / 不明 を出す
2. ★先に不採用（hardReject）を判定する★
3. 不採用でなければ点数を付ける
```

**2と3の順番を逆にしてはいけません。**
JANや品番が一致していても、袖丈やシーズンが食い違えば別商品です。
陽性の根拠で矛盾を上書きすると、そこから誤一致が入り込みます。

### 食い違ったら不採用にする項目

| 理由コード | 内容 |
| --- | --- |
| `wrongClub` | クラブが違う |
| `wrongManufacturer` | メーカーが違う |
| `wrongSeason` | シーズンが違う |
| `wrongKitType` | ホーム／アウェイ／サードが違う |
| `authenticityMismatch` | レプリカ／オーセンティックが違う |
| `genderMismatch` | 大人用／子供用などが違う |
| `sleeveMismatch` | 袖丈が違う（半袖／長袖／ノースリーブ） |
| `personalizationMismatch` | 無地／選手名入り／名入れが違う |
| `bundleMismatch` | セット商品なので中身が違う |
| `usedCondition` | 新品ではない |

**JANの不一致はここに入れていません。**
国内ECのJANはサイズ単位で付いていることが多く、
同じシャツでもS・M・Lで別のJANになります。
「JANが違う＝別商品」とすると、実測で21件中18件を取り逃がしました。

### 「書かれていない」を「一致」にしない

商品名に袖丈が書かれていなければ、それは
**一致でも不一致でもなく、未確認**です。点数も上げません。

判定結果には `unknownAttributes` として未確認の項目が残ります。
開発用サーバーでは、商品詳細ページの国内価格欄に
「開発用: 商品一致の根拠」という折りたたみで、
一致の根拠と未確認の項目が並んで見えます（本番ビルドには出ません）。

### 決めつけない表記

| 商品名の書き方 | 判定 |
| --- | --- |
| 「No.11 モハメド・サラー」 | 選手名入り |
| 「#7 ヴィルツ」「7.フロリアン・ヴィルツ」 | 選手名入り |
| 「マーキング入り」「背番号入り」 | 選手名入り |
| **「マーキング対応」「マーキング別売」** | **判断保留（人の確認へ）** |
| 「名入れ」 | 名入れ（購入者が指定） |
| 何も書かれていない | 無地 |

「マーキング対応」を選手名入りと読み違えると、
**無地の商品まで取り逃がします。**
逆に選手名入りを無地と読み違えると、**嘘の差額を出します。**
どちらでもないときは判断を保留します。

### 品番だけでランクBにしない

品番は商品説明の中にたまたま混ざることがあります
（「※JV6423とは別商品です」「関連商品: JV6423」など）。
品番の一致を信じるには、最低限

- クラブが一致していること
- シーズンか種類のどちらかが一致していること

が必要です。どちらも読み取れない商品名は、
属性一致どまり（自動採用しない）にします。

### 開発用のダミーJANを外部APIへ投げない

fixtureのJANには「2」で始まるインストアコード（店舗内管理用の予約番号）を
使っています。実在の商品に割り当てられることがないため、
本物のコードと衝突しません。

`isDistributableJan()` がこの範囲を弾くので、

- ダミーのJANでYahoo! APIを検索しません（呼び出しが1回むだになるため）
- ダミーのJANを「一致しなかった」という判断材料にもしません

### 実データでの結果

20商品・213件の候補に対して:

| | 件数 |
| --- | --- |
| 重大な食い違いで不採用 | 139件 |
| 人の確認へ（要確認） | 10件 |
| 自動採用 | 34件 |

**自動採用した34件はすべて目視で確認し、誤りはありませんでした。**

> これは「照合した範囲で誤りが見つからなかった」という意味です。
> 商品や出品の書き方は無数にあるため、
> **システム全体の精度が100%という意味ではありません。**

回帰テストは [`src/tests/matchingRegression.test.ts`](src/tests/matchingRegression.test.ts) にあります。
実データで見つけた誤一致をそのままテストにしてあるので、
照合を直すときは必ずここを通してください。

## 15.6. 楽天市場から国内価格を取る（第5段階）

Yahoo!ショッピングに加えて、楽天市場の商品検索APIを国内価格の提供元にしました。

```
Yahoo! API ──→ YahooRawProduct ─┐
                                ├→ DomesticOffer ─→ ★共通の照合エンジン★
楽天 API  ──→ RakutenRawItem ──┘         ↓
                                   DomesticMatch
                                         ↓
                                DomesticPriceSummary
```

**楽天専用の照合エンジンは作っていません。** 袖丈・マーキング・レプリカ／オーセンティック・
ホーム／アウェイの判定は、提供元が変わっても同じでなければ意味がないためです。

### 使うのは公式APIだけ

| 項目 | 内容 |
| --- | --- |
| API | 楽天市場 商品検索API（IchibaItem/Search） |
| エンドポイント | `https://openapi.rakuten.co.jp/ichibams/api/IchibaItem/Search/20260701` |
| 認証 | `applicationId`（クエリ）＋ `accessKey`（ヘッダー） |
| 1回の取得件数 | 最大30件（`hits`） |
| キャッシュ | `.cache/rakuten/`（gitignore済み） |

楽天市場の商品ページや検索結果HTMLのスクレイピング、非公開APIの利用はしません。

```bash
# サンプル応答で動作確認（認証情報なし・外部通信なし）
npm run data:rakuten:search -- --product=product-lfc-2526-home-replica --sample --dry-run

# 実APIで1商品だけ
npm run data:rakuten:search -- --product=product-lfc-2526-home-replica --dry-run

# Yahoo! と楽天を並べて確認
npm run data:domestic:compare -- --product=product-lfc-2526-home-replica
```

### 着手時に公式仕様を確認して分かった、指示書との違い

| | 指示書 | 実際の現行仕様 |
| --- | --- | --- |
| エンドポイント | `app.rakuten.co.jp` 想定 | `openapi.rakuten.co.jp`（旧は2026年5月14日に停止） |
| 認証 | `RAKUTEN_APPLICATION_ID` のみ | **`applicationId` と `accessKey` の両方が必須**（片方だけだと400） |
| JAN検索 | 「利用可能ならJANを最優先」 | **JAN検索のパラメータが存在しない** |

そのため `.env.local` には2つ必要です。

```
RAKUTEN_APPLICATION_ID=
RAKUTEN_ACCESS_KEY=
```

### JANが使えないこと

楽天の商品検索APIは、検索に使える商品の識別子が `keyword` / `itemCode` / `shopCode` / `genreId`
だけで、JANのパラメータがありません。**レスポンスにもJANの項目がありません。**

そのため検索の順番は、Yahoo!側とは違ってこうなります。

| | Yahoo! | 楽天 |
| --- | --- | --- |
| Level 1 | JANコード完全一致 | メーカー品番 |
| Level 2 | EAN（国内JANとして使える場合） | メーカー品番 + クラブ名 |
| Level 3 | メーカー品番 + クラブ名 | 商品属性 |
| Level 4 | 商品属性 | — |

**商品説明文からJANらしき数字を拾うことはしません。** 出品者が別商品のJANを書いていることがあり、
誤一致の元になるためです。

### 楽天の価格は、そのままでは比べられない

楽天の `itemPrice` は、**税別のことも、送料別のこともあります。**

| フラグ | 0 | 1 |
| --- | --- | --- |
| `taxFlag` | 税込 | **税別** |
| `postageFlag` | 送料込み | **送料別（金額は分からない）** |

- `taxFlag = 1`（税別）は、税込価格と並べると10%分だけ安く見えます。
  税率を掛けて直すこともできますが、商品によって8%／10%が違うので決め打ちせず、**人の確認へ回します。**
- `postageFlag = 1`（送料別）は、金額が取得できないので**送料不明**です。
  0円と決めつけると実際より安い総額になるため、総額を出しません。

### ポイントとクーポンを価格から引かない

```
商品価格 ¥10,000 ／ ポイント10倍  →  ★「実質 ¥9,000」としない★
```

ポイントは現金ではなく、付与条件も会員状態で変わります。差し引いた数字を「国内最安」として出すと、
**誰にも当てはまらない金額**を見せることになります。`rewardNote` に覚え書きとして残すだけです。
会員限定・アプリ限定・枚数限定のクーポンも同じ扱いです。

### ★新品／中古が取得できないこと★

**楽天の商品検索APIには、新品／中古を表す項目がありません。**

サカモノの採用条件は「新品であること」なので、既定では**楽天の候補は1件も自動採用されません。**
「中古の取り扱いが少ないから新品だろう」とは決めつけない、というこれまでの方針どおりです。

判断の根拠は `conditionEvidence` に残しています。

| 値 | 意味 |
| --- | --- |
| `api-new` | 提供元のAPIが新品と明言している（Yahoo!） |
| `api-used` | 提供元のAPIが中古と明言している／商品名に中古とある |
| `title-checked` | **APIに項目が無く、商品名に中古を示す語が無いことだけ確認した** |
| `unknown` | 確かめられていない |

`title-checked` は「新品である」証明ではありません。出品者が書き忘れているだけかもしれません。

方針を変えたい場合は、`AdoptionPolicy` を明示的に渡します。

```ts
isAdoptableOffer(offer, { acceptTitleCheckedCondition: true })
```

`data:rakuten:search` は、方針を緩めたときに何件増えるかを毎回表示します。
**実データで中古がどれくらい混ざるかを目視で確かめてから決めてください。**

### 提供元をまたいだ集計

`src/data/external/domestic/aggregate.ts` が、Yahoo! と楽天の候補をまとめます。

- **最安は送料込みで比べられるものを優先**します。1件も無ければ商品価格として示し、
  そのときは「送料込み最安」と表示しません（`PriceBasis`）。
- **中央値は送料込みで比べられるものだけ**で計算します。
- **同じ提供元の同じ掲載は二重に数えません**（安い方を残します）。
- **提供元が違えば、同じショップでも別の掲載として残します。**
  モールが違えば価格・送料・ポイントが違う、別の買い物だからです。
- 中央値から大きく外れた候補（半額以下 / 2倍以上）を `priceOutliers` として記録します。
  **第5段階では自動的に除外しません。** 安いこと自体は偽物の証拠にならないためです。

商品詳細ページでは、提供元が2つ以上あるときだけ内訳を出します。

```
国内最安 ¥8,980

Yahoo!ショッピング  ¥9,240
楽天市場            ¥8,980
```
